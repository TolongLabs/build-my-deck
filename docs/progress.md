The lesson is narrow and worth keeping: **validating the input and validating the serialized output are different checks**, and a normalizing parser can manufacture a hostile value out of an accepted one. Fixed by re-checking `pathname + search + hash` after resolution. Confirmed safe in real Chromium across 14 payloads and a 67-case fuzz — zero cross-origin escapes.

**N-2 and N-3, both consequences of wave 3's own CSRF fix.** Making the origin check compare against a configured `PUBLIC_ORIGIN` turned that variable into a hard production requirement, but `.env.example` never gained it, so an operator following the committed template could not boot the container. And the development default was a bare `http://localhost` with no port, while nothing here serves port 80 — so sign-out and account deletion were unreachable from a dev browser. Both fail closed rather than open, which is why they were mediums, but they are the same shape: a security control that is correct and unusable. `PUBLIC_ORIGIN=` is now in `.env.example` and the dev default derives from the configured port.
